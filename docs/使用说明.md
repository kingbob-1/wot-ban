# 使用说明（坦克世界封号案底查询工具 v1.0.1）

> 适用于 Windows 10 / 11、坦克世界 360 国服。
> 本工具把官方公开的历史封禁名单建成本地档案库，并把本地录像里的参战玩家与名单逐局比对。
> **历史封禁记录 ≠ 当前违规 / 当前开挂**；数据非官方口径，**禁止用于挂人、骚扰或任何处罚依据**。

---

## 1. 它能做什么、不能做什么

**能做**

- 查某个玩家**历史上是否被 360 官方封禁过**：几次、最近一次日期、原因、时长、来源批次与公告链接；
- 把一局录像里的 30 名玩家整体比对：谁上过名单一目了然（黄标 1 次 / 红标 ≥2 次）；
- 完整录像按账号 ID 精确匹配，partial（未打完）录像按昵称匹配并明确标注；
- 打开一局时按需查看盒子同款当局战绩（本局战力、伤害、经验等 16 项明细），完整局与 partial 局均可（partial 局按盒子战斗日志反查，受保留窗口限制）；
- 查看玩家综合战绩（任意玩家可查；选中玩家只显示本地缓存，点标题行右上角单个「刷新」手动刷新）；
- 本地维护名单库：启动自动检查更新、手动「更新名单」；名单库规模 / 批次完整性等诊断信息在 1.0 定稿界面不再单独展示。

**不能做**

- 不判断玩家**当前**是否开挂、不提供任何「挂狗鉴定」结论；
- 不提供游戏内 overlay、不注入游戏、不需要启动游戏；
- 不导出名单数据、不提供在线查询服务、不转发名单；
- 不覆盖亚服/国际服（它们没有公开封禁名单）。

## 2. 安装与启动

### 2.1 便携包（推荐）

1. 从 [GitHub Releases](https://github.com/kingbob-1/wot-ban/releases) 下载 Windows 便携包（zip，约 250 MB）；
2. 解压到任意目录（**不要**解压到需要管理员权限的目录，如 `C:\Program Files`）；
3. **双击目录内的 `坦克世界封号查询.exe`**。

便携包内已含启动器、Python 3.12、PySide6 与源码，**无需另外安装 Python**。数据、日志、配置都生成在解压目录内，删除目录即彻底卸载。首次启动会自动探测游戏目录/录像目录/我的账号（见 §2.2），不需要手动填写。

便携包根目录另带一个 `run.bat`（全 ASCII，包内生成的**备用入口**：调用包内 `runtime\pythonw.exe` 启动 `src\main.py`），仅在双击 exe 无法启动时用于排障；它与源码仓库里开发/排障用的 `bat\run.bat` 不是同一个文件，普通用户日常无需使用。

### 2.2 首次启动与配置（通常无需配置）

程序**默认开启环境自动探测**，首次启动时会自动识别以下三项并写入配置，**无需手点或填写路径**；探测结果可在顶栏「重新检测」按钮的 tooltip 中查看：

| 项目 | 探测方式 |
|---|---|
| 游戏安装目录 | 读取系统注册表卸载项（「坦克世界」/ World of Tanks / Wargaming Launcher）→ 常见盘符下的 `World_of_Tanks_CN` 等目录扫描 → 按「含 `replays` 子目录 + 最新录像时间 + 录像数量」评分择优 |
| 录像目录 | 游戏目录下的 `replays` 子目录 |
| 我的账号（昵称 / 账号 ID） | 只读解析录像目录中**最新一份录像**（含 partial）的内嵌玩家信息（`playerID` / `playerName` / 对局时间） |

- 探测成功：顶栏「重新检测」按钮的 tooltip 会显示当前游戏目录 / 录像目录 / 我的账号，无需设置；
- 探测失败（绿色版游戏、注册表缺失、录像目录自定义等）：录像区提示会显示「未检测到游戏目录/账号」，可点顶栏 **「重新检测」** 或 **「手动选择游戏目录」**；手动选择后会**记住**（写入 `config.local.json`，该文件不入库、不上传）；
- 名单归档目录默认在程序目录内（`data\archive`），自动创建，无需配置。公开版首次启动会自动从官方接口抓取名单。

**高级配置（可选）**：确需固定路径时，在程序目录（项目根，即 `src\main.py` 所在 `src\` 目录的上一级）新建 `config.local.json`，按需覆盖：

```json
{
  "game_dir": "X:\\World_of_Tanks_CN",
  "replay_dir": "X:\\World_of_Tanks_CN\\replays",
  "auto_detect": true
}
```

- 示例中的 `X:` 是占位盘符，请换成游戏实际安装盘符；
- 显式填写的路径优先于自动探测；`auto_detect: false` 可完全关闭探测；
- 便携包/绿色版用户如把名单归档放到别处，也可加 `"archive_dir": "archive"`（相对程序目录）；
- 该文件已被 `.gitignore` 排除，不会被提交、不会上传；改完重启程序生效。
- 也可以随时用录像区的「手动选择…」临时打开单个录像文件，不依赖录像目录配置。

## 3. 首次启动与名单库

第一次启动时程序会：

1. **自动探测本机环境**：游戏安装目录 → 录像目录 → 我的账号（注册表 + 最新录像内嵌信息，见 §2.2），结果用于录像区定位与「重新检测」按钮的 tooltip（顶栏不显示路径），**无需手动设置**；
2. 自动创建数据库 `data\wotban.db`、日志目录 `log\` 与名单归档目录；
3. 自动触发一次名单检查/抓取（**约 5–6 分钟**，取决于网络；官方接口低频只读，≥2 秒/请求）；
4. 抓取完成后，结果与进度提示显示在录像区进度行和底部状态栏；名单库规模 / 批次完整性等诊断信息在 1.0 定稿界面不再单独展示，如需排查可只读查看 `data\wotban.db` 或反馈时提供 `log\` 日志。

> 公开版首次运行自动抓取的是官方 **CSV 系列名单（96 期，2021-08-16 起，约 25.6 万条）**。2020-08 ~ 2021-08 的 18 期 xlsx 是官方公告附件形式，不在自动抓取范围内（本机开发者档案额外包含这 18 期，故完整口径为 322,941 条源记录 / 322,806 条去重入库）。

若首次抓取失败：看界面提示与 `log\` 下的日志；确认能正常访问 `profile.wg.360.cn`（需要时可配置系统代理后重试），稍后点「更新名单」重试。**更新期间可随时取消。**

## 4. 主界面速览

默认窗口 **1920×1080（16:9）**，屏幕可用区域不足时等比收缩；窗口可缩放，最小 1280×720。

- **顶部（单行）**：工具名 + 版本号，右侧**三个按钮**——**「重新检测」「手动选择游戏目录」「更新名单」**。顶栏不显示名单库元信息，也不显示本机环境路径；路径见「重新检测」按钮的 tooltip；
- **中间「录像区」**：`最新完整录像` / `全部录像` / `手动选择…` **三个入口** + 当前对局下拉框（弹窗最多显示 15 局，更多用竖向滚动条查看；带完整 / partial 徽标，下拉列表条目也尽量从文件名提取并显示车名）；「当前对局」文案显示 **时间 · 中文地图名 · 本人本局车名 · 完整/partial · 人数**（如 `2026-11-15 01:08 · 斯杜季昂奇 · 五式重战 · partial（未打完） · 30 人`，只显示名称、不显示代码）+ 进度条 + `取消`；
- **左下「查询结果」表**：本局全部玩家按红绿方上下两组展示（绿方 = 本人队在上），**本人（录像者）行浅蓝底 + 昵称加粗**（封禁黄 / 红底色优先）；标题行显示本局胜负平 + 比分（列含义见第 7 节），上方有筛选与「显示 N / M 人」；
- **右下「明细」面板**：选中玩家的全部封禁记录、16 项盒子同款当局战绩（每行 2 组，不需要横向滚动）、综合战绩缓存与标题行右上角单个「刷新」按钮；面板内只保留数据与标题，不单列来源 / 口径提示行；
- **底部**：固定免责声明与状态栏——进度、更新结果、战绩降级等提示都在这里显示。

## 5. 更新名单

- **自动**：每次启动检查一次；程序运行期间每 **6 小时**检查一次；检查结果会显示在底部状态栏，遇到风控时会在 `log\` 中留下中文日志。
- **手动**：点「更新名单」立即检查（`force` 模式，忽略 6 小时间隔）。
- **只读**：全部为官方公开接口的只读 GET（≥2 秒/请求、无并发）；不登录、不绕过风控。
- **风控中止**：遇到 403 / 412 / 429 / 503 会立即中止并给出中文提示，**不会重试绕过**，也不会把本次记为已检查（稍后仍会重新检查）。
- **漏期说明**：程序不创建 Windows 计划任务。程序未运行的期间官方若发布了新一期，**该期约 100 个账号 ID（wgid）会永久错过**（官方只提供最新一期前 100 条 ID，无法回补）；历史封禁记录本身仍会补抓，只是当期的账号 ID 缺失。
- **新增批次**：先存档最新一期 JSON 的 `wgid` → 再按日期间隔下载缺失期 CSV → 入库去重，重复运行幂等。

## 6. 选择与扫描录像

| 入口 | 行为 | 适用场景 |
|---|---|---|
| 最新完整录像 | 定位最近一局打完的完整录像并加载 | 刚打完一局想立刻看 |
| 全部录像 | 扫描整个录像目录（首次较慢，之后走增量缓存） | 大范围检索 |
| 手动选择… | 直接打开单个 `.wotreplay` 文件 | 录像目录不固定/只想看某一局 |

- 录像目录默认使用**自动探测**的游戏目录下 `replays`（见 §2.2）；探测不到或想换目录时，可在界面「手动选择游戏目录」或按 §2.2 在 `config.local.json` 显式指定 `replay_dir`；
- 扫描时显示进度，可随时「取消」（后台线程执行，不卡界面）；
- 损坏/不完整文件会被跳过，不中断整体扫描；
- **完整录像**（打完的局）可解析出全部玩家账号 ID；**partial 录像**（未打完，约占 56%）只有昵称/军团/坦克信息，界面标注「partial」并按昵称匹配；partial 局同样可以加载盒子当局战绩（见第 9 节）；
- 同一录像重复扫描命中增量缓存，速度很快；
- **启动自动加载**：界面打开后会自动按「全部录像」扫描一次并打开最近一局（首次扫描较慢、之后走增量缓存）；手动入口仍为上面三种。

## 7. 看查询结果

结果表共 **24 列**（顺序与标题固定；前 8 列为封禁 / 匹配信息，后 16 项与盒子当局明细同序）：

> 昵称 / 账号 ID / 军团缩写 / 封禁次数 / 最近封禁日期 / 原因 / 时长 / 匹配方式 / 车型 / 本局战力 / 经验值 / 射击 / 击穿 / 造成伤害 / 被击中 / 受到的潜在伤害 / 装甲抵消伤害 / 发现敌人 / 击伤敌方战车 / 击毁敌方战车 / 协助盟友造成伤害 / 占领敌方基地点数 / 保卫基地防御点数 / 行驶里程

- **红绿方分组**：结果表按「绿方 · 我方（N 人）」在上、「红方 · 敌方（N 人）」在下两组展示；**绿方 = 录像者本人所在队**（不是固定 team 1），60 人对局同样分两组。组头行只作分组标识，不可选中；
- **本人行高亮**：录像者本人的行用**浅蓝底 + 昵称加粗**标出（与绿方分组用同一套录像者识别口径）；若本人也上过封禁名单，**黄 / 红底色优先**，昵称仍加粗；选中任意行时用半透明叠加，不会盖掉封禁标色与本人浅蓝底；
- **胜负平标题行**：表格上方标题显示「查询结果 · 平局 14v6」这类文案——胜利绿色、平局橙色、失败红色；比分来自盒子（如 14v6）。完整录像即使盒子不可用也会用录像胜负给出「胜利 / 平局 / 失败」（此时可能没有比分）；partial 录像在战斗日志反查成功后显示；
- **黄底 = 历史封禁 1 次；红底 = 2 次及以上**；
- **匹配方式**：
  - `ID 确认`：完整录像的账号 ID 与名单 `wgid` 精确一致（最可靠）；
  - `昵称匹配`：该记录无账号 ID（历史批次），按同一昵称视为同一人；
  - `仅昵称匹配`：partial 录像没有账号 ID，只能按昵称匹配（计入黄/红，但存在同名不同人的可能）；
- **排序**：每组内默认按 **封禁次数降序 → 本局战力降序 → 伤害降序**（没有战绩数据的行排在后面）；点击表头只在组内切换排序，红绿两组的先后顺序不变；
- **本局战力**：显示为四舍五入后的整数（如 868.46 → 868），其余数字带千分位；
- **车型 / 地图 / 当前对局车名**：`车型` 显示游戏中文车名（如「五式重战」，IS-7 等保持原文），来自盒子车名或本机游戏本地化文件；「当前对局」下拉与地图标签显示中文地图名（如「斯杜季昂奇」，查询完成后刷新），并在其后显示**本人本局车名**（如 `… · 斯杜季昂奇 · 五式重战 · partial（未打完） · 30 人`）；车名映射失败时省略该段，**界面不显示车辆 / 地图代码**；
- **一屏 30 人**：默认 1920×1080 窗口下，30 人 + 2 个组头一屏完整显示、不需要纵向滚动；60 人对局保留纵向滚动条，一屏约 30 人。窗口缩小或系统缩放较大时，30 人局也可能需要滚动；
- **筛选**：「只看命中」只显示上过名单的玩家；「仅看 ID 命中」只显示 ID 精确匹配的行；「标色」可按黄/红筛选；
- **无悬停提示**：查询结果区域（结果表所有列、结果标题、筛选控件与统计文字）**不提供鼠标悬停提示**，各列口径以本说明与右侧明细面板为准；顶栏按钮与明细面板的提示不受影响；
- 底部汇总显示「本局 N 人 · 命中 M 人（ID 确认 / 昵称匹配 / 黄标 / 红标）」，并注明默认排序口径。

## 8. 看玩家明细

在结果表点击任意一行（组头行除外），右侧「明细」面板显示：

- 玩家昵称、匹配方式、封禁次数（黄/红徽标）、账号 ID（partial 显示「—（partial 录像无 ID）」）、军团、本局坦克（游戏车名）、阵营（`绿方 · 我方` / `红方 · 敌方`）；
- **封禁记录表**：每条记录的批次日期、原因、时长、累计次数、来源类型（CSV / xlsx / JSON），以及来源批次 / 公告链接（可点击查看、可复制）/ 抓取时间——可核对官方原始出处；
- **当局战绩**：按盒子明细顺序展示 16 项（每行 2 组，长车名也不会撑出横向滚动条）——坦克 / 本局战力 / 经验值 / 射击 / 击穿 / 造成伤害 / 被击中 / 受到的潜在伤害 / 装甲抵消伤害 / 发现敌人 / 击伤敌方战车 / 击毁敌方战车 / 协助盟友造成伤害 / 占领敌方基地点数 / 保卫基地防御点数 / 行驶里程；战绩加载中显示「…」，不可用时显示「—」并看底部提示；
- **综合战绩**：选中玩家只展示本地已缓存结果（含盒子的数据更新时间与本地缓存时间），不发请求；需要更新时点标题行右上角的「刷新」（见第 10 节）；
- 未命中名单时显示「未命中任何历史封禁记录」。

## 9. 当局战绩（按需加载）

- 打开一局时会自动在后台加载该局的盒子当局战绩（16 项明细，不阻塞封禁查询）；仅最近 180 天内的对局会发起请求，超期局直接显示不可用；
- **完整录像**：用录像自带的 `arena_id` 请求盒子 `battledetail`；
- **partial 录像（中途退出 / 未打完）**：录像没有结算块、没有 `arena_id`，程序按「录像对局时间 + 录像者坦克」到盒子**战斗日志**反查这场对局的 `arena_id`，再取 `battledetail`。限制：
  - 仅最近 180 天内触发；战斗日志约保留最近 **1075 局**（实测 215 页 × 每页 5 条，第 216 页起返回重复页），超出保留窗口的局不可用；
  - 战斗日志时间只精确到分钟，需要与录像对局时间「同一分钟」且录像者坦克代码一致才算匹配，否则判为未匹配；
  - 反查不逐页扫描：按「时间估算页 + 历史锚点校正 + 封顶重复检测」定位目标页，单局最多 **8 次**战斗日志页面请求、相邻请求至少间隔 **3 秒**，命中后再发 1 次当局明细请求；遇到盒子风控（403）立即停止本局请求，连续失败后进入约 **10 分钟冷却**，冷却期间不发任何盒子请求；
- **缓存**：只要是成功拿到的对局战绩，就**永久缓存在本地数据库、不会二次抓取**——180 天窗口内同一局再次打开直接显示缓存（**0 请求**）；超过 180 天后按超窗口径显示不可用。删除本地数据库才会重新抓取。失败（限流、未匹配、超窗、网络异常）不写入缓存，稍后可重试；
- **降级**：任何一步失败都不影响封禁查询，战绩列显示「—」，具体原因在底部状态栏给出中文提示；
- 战绩来自偶游盒子，**非官方数据、仅供参考**；「本局战力 ≠ 伤害」，各项含义见本节与第 7 节说明（查询结果区域不设悬停提示）。

## 10. 综合战绩（单个「刷新」按钮）

- **不会自动请求**：选中玩家时只展示本地已缓存的综合战绩（含盒子的数据更新时间与本地缓存时间），**不发任何请求**；没有缓存就显示「—」；
- **单个「刷新」按钮**：综合战绩标题行右上角只有一个「刷新」按钮；点击才向盒子请求，且**强制忽略缓存重新拉取**，结果随后展示在明细面板（含数据更新时间 / 缓存时间）；
- **任意选中玩家都可查**：不再要求玩家命中过封禁名单；**partial 录像玩家没有账号 ID 时按昵称查询**；既无账号 ID 又无昵称时提示「缺少账号信息」；
- 数据来自偶游盒子 `index` 页面，口径为「**最近 1500 场标准局**」，非官方、仅供参考（鼠标悬停在明细面板的「综合战绩」标题或「刷新」按钮上可查看口径提示）；
- 限流 ≥2 秒/请求；失败或限流时在底部状态栏与明细面板给出中文提示，不影响封禁查询。

> 综合战绩结果缓存在本地数据库中：选中玩家直接展示缓存（零请求），只有点「刷新」才会重新请求；界面不会自动刷新。

## 11. 维护与排查（数据 / 日志）

1.0 定稿界面不再提供独立的名单库状态页，名单库批次数 / 条数 / `wgid` 覆盖 / 缺失批次 / 录像索引数等诊断信息不再在界面单独展示，日常使用无需关注。如遇名单查询异常，可以：

1. 查看程序目录下的 `log\*.txt` 运行日志（按启动时间分文件）；
2. 用任意 SQLite 工具**只读**打开 `data\wotban.db` 查看名单库与录像索引数据（不建议手工修改）；
3. 反馈问题时附上 `log\` 日志与界面提示原文。

需要重新抓取名单时，点顶栏「更新名单」即可（公开版首次启动也会自动抓取）。数据文件与日志的具体位置见第 12 节。

## 12. 数据、配置与日志位置

| 内容 | 位置 | 是否可删 | 说明 |
|---|---|---|---|
| 数据库 | `data\wotban.db` | 可删（下次重建） | 名单库 + 录像索引 + 战绩缓存（当局战绩永久缓存；综合战绩缓存，选中展示、点「刷新」重查） |
| 日志 | `log\*.txt` | 可删 | 按启动时间分文件；反馈问题时附上 |
| 本机配置 | `config.local.json` | 可删（恢复自动探测） | 游戏目录/录像目录/我的账号等本机路径与探测结果；不入库不上传 |
| 名单归档（本机） | `archive_dir` 指向的目录（默认 `data\archive`） | 可删 | 抓取缓存/归档（内部维护用，普通用户无需操作） |
| 启动器 | `坦克世界封号查询.exe` | 不建议删 | 薄启动器：负责找 `pythonw.exe` 并拉起 `src\main.py`；更新源码无需重编 |
| 程序配置默认值 | `src\config.py` | 不建议改 | 路径/接口/限流阈值集中定义 |

> 名单库、录像索引与战绩缓存都保存在本地数据库内：删除数据库（或整个程序目录）会一并清空，之后需要重新抓取名单、重新打开对局请求战绩。

## 13. 常见问题排查（FAQ）

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 双击 `坦克世界封号查询.exe` 无反应/闪一下 | 启动器找不到 `pythonw.exe` / 目录被移动后缺少运行时 | 启动器会弹中文提示；便携包请重新解压完整包；源码方式请用 `bat\run.bat`（依赖工作区共享运行时 `..\runtime\python.exe`），或确认 PATH 中有 `pythonw.exe` |
| 启动器提示「找不到 src\main.py」 | exe 被单独拷贝到别处（旁边没有 `src\main.py`） | 保持 exe 与 `src\`、`runtime\`（便携包）在同一个程序目录，且 `src\main.py` 位于该目录的 `src\` 子目录内 |
| 提示「未检测到游戏目录/账号」 | 绿色版游戏、注册表项缺失、录像目录自定义 | 点「重新检测」；或「手动选择游戏目录」（选择后自动记住）；也可按 §2.2 在 `config.local.json` 指定 |
| 双击 `bat\run.bat` 一闪而过 | `bat\run.bat` 依赖工作区 `..\runtime\python.exe`；公开用户用错入口（便携包内是根目录的 `run.bat`） | 日常请用 `坦克世界封号查询.exe`；源码开发才用 `bat\run.bat`，或直接 `python src\main.py` |
| 提示缺少 PySide6 | 源码环境未安装依赖 | `python -m pip install PySide6` |
| 首次更新很慢或失败 | 网络不通/代理问题/官方接口变更/被风控 | 检查网络与代理；稍后重试；看 `log\` 中文错误；遇到 429/403 停止重试 |
| 扫描不到录像 | 探测/选择的录像目录没有 `.wotreplay` | 确认游戏内开启「保存录像」；在界面「手动选择游戏目录」修正；或「手动选择…」单个文件 |
| 「当前对局」多了一段车名 / 本人行为什么有浅蓝底 | — | 「当前对局」在中文地图名后显示本人本局车名（只显示名称、不显示代码）；结果表中录像者本人行用浅蓝底 + 昵称加粗标出，本人若命中封禁名单则黄 / 红底色优先 |
| 为什么以前 partial（中途退出）局拿不到盒子战绩 | 以前只认录像自带的 `arena_id`；partial 录像未打完、没有结算块，取不到 `arena_id`，于是根本不发请求 | 本轮起改为按盒子战斗日志反查 `arena_id`，正常打开该局（180 天内）会尝试自动加载 |
| 现在 partial 局怎么查盒子战绩 | — | 直接选中该局即可，无需额外操作；若提示不可用，可能是超出战斗日志保留窗口、时间/坦克匹配不上或盒子限流，可稍后重试或换更近的局 |
| 盒子战斗日志的保留窗口 / 封顶页是什么 | 盒子战斗日志每页 5 条，实测有效数据约 215 页（约 1075 局），**第 216 页起返回完全重复的页**（封顶），更早的对局查不到 | 属盒子侧保留限制，正常现象；工具按重复页检测自动判断封顶，不逐页扫描，超出窗口的局不可用 |
| 对局战绩 / 综合战绩的缓存与刷新 | — | 对局战绩成功即**永久缓存**（同一局再开 0 请求）；综合战绩选中玩家只显示本地缓存、不发请求，点标题行右上角的**单个「刷新」**才强制重查；**任意选中玩家都可查**，partial 局按昵称查 |
| 提示「该局超出战绩接口 180 天范围」 | 对局超过 180 天 | 正常提示，不发起战绩请求；战绩明细不可用（完整局仍可从录像胜负显示「查询结果 · 胜利/失败」，但无比分），封禁信息照常可查 |
| 提示 partial / 仅昵称匹配 | 录像未打完，没有玩家账号 ID | 正常现象；昵称匹配计入黄/红，注意同名不同人可能；partial 局仍会尝试反查盒子当局战绩，失败时看底部提示 |
| 战绩一直「不可用」 | 超期局、partial 局超出战斗日志保留窗口或无法匹配、盒子限流或网络失败 | 属正常降级；主表封禁查询不受影响；失败的局不缓存，可稍后重新打开该局重试 |
| 名单库为空 | 首次未抓取/抓取失败 | 点「更新名单」重新抓取；仍为空则看 `log\` 日志与界面提示并反馈 |
| 想查看名单库规模 / 缺失批次等诊断信息 | 1.0 定稿界面不再提供独立的名单库状态页 | 可只读查看 `data\wotban.db`，或反馈时提供 `log\` 日志（普通用户无需关注） |
| 界面按钮点了没反应/卡住 | 上一次后台任务未结束（更新/扫描/综合战绩刷新进行中） | 等进度条完成或点「取消」；仍异常请重启程序并附日志 |
| 杀毒软件报毒 | 薄启动器 exe + 内嵌 Python 运行时，个别杀软对未签名 exe/解释器敏感 | 本项目代码开源、不联网上传数据；可加入信任，或改用源码方式运行 |
| 想彻底卸载 | — | 关闭程序后直接删除整个程序目录（数据/日志/配置都在目录内）；源码方式另删 `data\`、`log\`、`config.local.json` |

反馈问题时请提供：`log\` 下对应日志、界面提示原文、Windows 版本、是否便携包；**请勿附带包含个人信息/账号信息的截图**。
