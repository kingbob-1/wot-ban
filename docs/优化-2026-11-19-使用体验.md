## 2. 实现方案

### 2.1 数据层：新字段、partial 反查与缓存语义

- `src/models.py`：`BattlePlayerStats` 新增 `hits_received / potential_damage / damage_blocked / vehicles_damaged / assisted_damage / defense_points / mileage / tank_code`；`BattleStats` 新增 `outcome / outcome_label / score / arena_source`；服务层结果对象新增 `cached`（本次是否命中本地缓存）。
- `src/stats/box_client.py`：
  - **全字段解析**（盒子 battledetail 口径）：`directHitsReceived`→被击中、`potentialDamageReceived`→受到的潜在伤害、`damageBlockedByArmor`→装甲抵消伤害、`damaged`→击伤敌方战车、`damageAssistedRadio + damageAssistedTrack`→协助盟友造成伤害、`numDefended`→保卫基地防御点数、`mileage`→行驶里程、`vehicle_icon`→坦克 slug；`tank_title` 直接作为车名。
  - **partial 反查（时间估算页 + 锚点校正 + 封顶重复检测）**：解析盒子战斗日志页（每页 5 条：`arena-id / arena-win / 坦克 slug / MM-DD HH:MM / 比分`）→ 按「对局时间同一分钟 + 坦克 slug 一致」筛候选 → 命中后请求 battledetail；`arena-win`（1 胜 / 2 平 / 0 负）换算胜负平。
  - **页号估算（不线性扫页）**：用持久化的「页号 → 时间范围」锚点做插值 / 有界割线外推（局部单步最多 8 页、页距过大的锚点对不插值、首次单锚点按约 2 页/天粗估），再在 ±邻域校正；重复估算页时按目标时间方向选邻页。
  - **封顶页检测**：某页的「arena-id 列表 + 时间列表」与已探测页完全相同即判定为封顶重复页，缓存封顶页与覆盖下界；目标早于下界直接判「超出保留窗口」，不再发请求。
  - **预算与风控**：单局战斗日志页请求预算 **8 次**、相邻请求间隔 **≥3 秒**；任一页失败（含 403）立即停止；进程级熔断：连续 2 次风控 / 网络失败进入 **600 秒（约 10 分钟）冷却**，冷却期内所有盒子请求一律不发。
  - **缓存**：成功映射按录像路径幂等写入 DB（二次打开 0 网络）；对局战绩成功即最终版（按 `arena_id` 永久缓存，无 TTL）；锚点表 24 小时过期重探；封顶页长期复用。
- `src/app/service.py`：完整局用录像自带 `arena_id` 并可用录像胜负兜底标题；partial 局走上述反查链路；两类局都受 180 天窗口保护（超窗零请求）；构建录像信息时用 `game_names.map_name()` 补中文地图名。
- `src/store/db.py`：新增 `battlelog_anchor`（页→时间锚点）、`battlelog_cap`（封顶页）、`replay_arena_map`（录像路径→arena）等表，幂等迁移，不破坏既有名单 / 录像索引数据。
- `src/config.py`：预算 / 间隔 / 窗口 / 缓存口径集中配置，不写死机器路径。

### 2.2 车名映射：`src/game_names.py`（新增，纯标准库）

- 只读**本机游戏安装目录**的 gettext 本地化文件，不联网：车辆取 `res/text/lc_messages/{nation}_vehicles.mo`（兜底 `igr_vehicles.mo`、`multinational_vehicles.mo` 等），地图取 `arenas.mo` 的 `{code}/name`。
- 输入兼容录像代码（`japan:J20_Type_2605`）、盒子 slug（`japan-j20_type_2605`）、裸代码与地图变体；国家别名 `uk ↔ gb`；大小写不敏感。
- 失败一律返回 `None`（无游戏目录 / 无 `.mo` / 损坏 / 未知代码），绝不抛异常；进程内缓存首次解析约 0.03 秒；`game_dir=None` 时复用动态环境探测，不写死盘符。

### 2.3 界面

- **列契约**：`src/ui/table_model.py` 固定 24 列（前 8 列为封禁 / 匹配信息，后 16 项与盒子当局明细同序）：昵称 / 账号 ID / 军团缩写 / 封禁次数 / 最近封禁日期 / 原因 / 时长 / 匹配方式 / 车型 / 本局战力 / 经验值 / 射击 / 击穿 / 造成伤害 / 被击中 / 受到的潜在伤害 / 装甲抵消伤害 / 发现敌人 / 击伤敌方战车 / 击毁敌方战车 / 协助盟友造成伤害 / 占领敌方基地点数 / 保卫基地防御点数 / 行驶里程；删除旧「阵营」「命中率」列。
- **分组与排序**：绿方 = 录像者本人所在队（由 `ReplayDetail.recorder_dbid / recorder_name` 反查，不写死 team==1），绿方组在上；组头行跨列合并且不参与选中；组内默认排序链 封禁次数 → 本局战力 → 伤害（None 置后），表头点击只改组内顺序。
- **格式化**：本局战力用 `Decimal` 十进制 half-up 取整并带千分位；其它数值列千分位，缺失显示「—」；车型展示优先级 = 盒子 `tank_title` → `game_names.vehicle_name()` → 原值。
- **标题行**：`main_window` 在异步战绩到达后把「查询结果」更新为「查询结果 · 平局 14v6」，按胜负平换色（胜绿 / 平橙 / 负红），加载中显示占位。
- **布局**：结果表 7.5pt 字体、24px 行高、压缩列宽；默认窗口 1920×1080 下 30 人 + 2 组头一屏无纵向滚动；60 人保留滚动条。
- **明细面板**：`widgets.py` 按盒子顺序展示 16 项当局战绩（坦克 / 本局战力 / 经验值 / 射击 / 击穿 / 造成伤害 / 被击中 / 受到的潜在伤害 / 装甲抵消伤害 / 发现敌人 / 击伤敌方战车 / 击毁敌方战车 / 协助盟友造成伤害 / 占领敌方基地点数 / 保卫基地防御点数 / 行驶里程）；综合战绩选中只显示缓存，新增「查看综合战绩」「刷新综合战绩」按钮。

### 2.4 缓存口径汇总

| 对象 | 键 | 有效期 | 刷新方式 |
|---|---|---|---|
| 对局战绩（battle_stats） | `arena_id` | **永久**（成功即最终版） | 界面不提供刷新；同局再次打开 0 请求 |
| partial → arena 映射 | 录像文件路径 | 永久 | 删除本地数据库后重新反查 |
| 战斗日志页锚点 | 账号 + 页号 | 24 小时 | 过期后自动重新探测 |
| 战斗日志封顶页 | 账号 | 长期 | 重复页检测自动更新 |
| 玩家综合战绩 | 游戏账号 ID | **自然日** | 「刷新综合战绩」强制重查 |

> 缓存不设 TTL 不等于绕过窗口限制：对局战绩的**可用性**仍受 180 天窗口约束——超窗后即使有缓存也按「不可用」展示，且不会为此二次请求；「永久缓存」指成功数据不会因时间过期而重新抓取。

## 4. 偏差与限制

1. **请求预算口径**：需求写「单局 ≤8 请求」，实现为**战斗日志页请求预算 ≤8**，命中后另发 1 次 battledetail（单局最多 9 次请求）；实测 A 局共 2 次、B 局重试共 7 次。
2. **封顶页数字**：本机账号实测有效数据到第 **215 页**（≈1075 局），第 216 页起返回完全重复页；界面失败提示中的「战斗日志约保留最近 1100 局」是近似口径（与 1075 不矛盾）。实现**不写死页数**，按重复页检测自动钉住封顶页并缓存；自动探测起点页默认 240（历史经验值，仅兜底）。
3. **匹配为保守精确匹配**：要求「同一分钟 + 坦克 slug 一致」；跨分钟、坦克无法确认或多局同分钟同坦克时可能匹配不到或取首个候选（按时间差升序），宁可判不可用也不猜测。
4. **partial 反查仅打开该局时触发**，且仅最近 180 天内；不支持批量预热历史 partial 局。
5. **综合战绩按自然日缓存**（不是滚动 24 小时）：跨自然日后的第一次「查看」会重新请求，这是为避免一天多次请求的设计口径。
6. **30 人一屏无滚动依赖默认 1920×1080 逻辑窗口**；窗口缩小或系统缩放较大时会出现纵向滚动条（功能不受影响）。
7. **紧凑列宽会截断长昵称 / 长车名**：证据中「车型」默认宽 66px，部分内容需 88~135px；可拖拽列宽查看，车型 tooltip 可看原始代码。
8. **真实网络样本有限**：本轮真实盒子复测仅 2 例 partial（受风控预算约束），估算器另以离线单测覆盖（含真实锚点回归）；未做更大批量真实回归。
9. 失败的对局不写入缓存；盒子风控冷却期间（约 10 分钟）不发任何请求，需要等待后重试。
