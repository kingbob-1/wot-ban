# P4 薄 exe 启动器（原创坦克图标）

> 版本：v0.2 阶段交付物　｜　对应任务：T19（薄 exe 启动器 + 原创坦克图标）
> 结论：**已在开发机实测通过**——exe 37.5 KB、图标原创多尺寸、`--version`/`--init-db` 透传正常、无参数启动 GUI 存活。

## 1. 定位

给最终用户一个**双击即用**的入口 `坦克世界封号查询.exe`：它本身**不含 Python 解释器、不含业务代码**，
只是定位同目录的 `main.py` 并拉起合适的 Python 解释器。因此：

- 体积小（37.5 KB，预算 ≤100 KB）；
- **更新产品源码后无需重新编译 exe**（见第 5 节）；
- 不采用 PyInstaller 打包（避免大体积与杀软误报，见 `docs/P3-集成验证.md` 的选型结论）。

## 2. 产物与文件清单

| 文件 | 作用 |
| --- | --- |
| `坦克世界封号查询.exe` | 构建产物（项目根，双击入口），C# Winexe 薄壳 |
| `assets/app.ico` | 原创坦克剪影图标（16/32/48/64/128/256 六种尺寸，单文件 27.7 KB） |
| `scripts/build_launcher.py` | 一键构建脚本：画图标 → 生成 C# 源码 → csc 编译 → 部署 → 自检 |
| `build_launcher.bat` | 双击构建入口（全 ASCII + CRLF，调用上面的 Python 脚本） |
| `tests/test_launcher.py` | 启动器产物回归测试（图标尺寸 / exe 体积 / `--version` / bat 规范） |

## 3. 使用

### 3.1 双击启动 GUI

双击 `坦克世界封号查询.exe` 即可。启动器会：

1. 把**自身所在目录**当作应用根目录（exe 可放在任意路径，不写死本机路径）；
2. 要求同目录存在 `main.py`，缺失时弹中文 MessageBox 提示当前目录；
3. 按第 4 节顺序解析 `pythonw.exe`，以应用根目录为工作目录启动 `main.py`，随后**立即退出**
   （GUI 进程独立运行，启动器不常驻）。

### 3.2 命令行参数（原样透传）

启动器把收到的全部参数原样传给 `main.py`：

```
坦克世界封号查询.exe --version      # 打印版本后退出（退出码 0）
坦克世界封号查询.exe --init-db      # 初始化/升级本地数据库
坦克世界封号查询.exe --mock         # 演示数据启动 GUI
坦克世界封号查询.exe --config PATH  # 指定配置文件
```

有参数时**优先使用 `python.exe`**（控制台解释器），因此 `--version` / `--init-db` 的输出可见；
在 `cmd` 中会复用当前控制台窗口，在 PowerShell 中重定向/管道也会以 UTF-8 输出。

> PowerShell 注意：`.exe` 是 GUI 子系统程序，PowerShell 用 `& .\坦克世界封号查询.exe --version`
> **不会等待进程结束**，`$LASTEXITCODE` 也为空。请在 `cmd` 中运行，或改用
> `Start-Process -Wait -PassThru .\坦克世界封号查询.exe -ArgumentList '--version'`。

## 4. 解释器解析顺序（零本机路径硬编码）

exe 运行时按以下顺序找解释器，找到即用：

| 场景 | 顺序 |
| --- | --- |
| 无参数（GUI） | `<app根>\runtime\pythonw.exe` → `<app根>\..\runtime\pythonw.exe`（开发布局）→ PATH 中的 `pythonw.exe` |
| 有参数（CLI） | `<app根>\runtime\python.exe` → `<app根>\..\runtime\python.exe`（开发布局）→ PATH 中的 `python.exe`（再回退 `pythonw.exe`） |

- 便携包形态：把 `python\` 目录改名/放置为应用根下的 `runtime\` 即可，启动器直接命中第一顺位；
- 开发机形态：直接放在 `<项目目录>\`，会命中第二顺位 `..\runtime\`（工作区共享解释器）；
- 任何情况下都失败 → 弹中文 MessageBox，列出**已尝试的完整路径**与排查建议。

启动时还做了两个细节处理：

- 参数模式若标准输出被重定向（管道/文件重定向），启动器把子进程输出以 **UTF-8** 转发，
  与 `main.py` 强制 UTF-8 输出的行为一致；若标准输出不可用（如带参数双击），
  改为把输出显示在 MessageBox 里，避免"双击了却看不到结果"；
- 启动器自身标准输出是控制台时，复用父控制台，不额外弹窗。

## 5. 更新源码无需重编 exe

exe 只负责「找 main.py + 找 Python + 传参数」，业务逻辑全部在 `main.py` / `src\` 中：

- **改业务代码、界面、数据层 → 直接改源码即可，无需重新编译 exe**；
- 只有当**启动壳本身**变化时才需要重编：换图标、改解释器解析顺序、改错误提示文案、改 exe 文件名；
- 重编命令见第 6 节，产物覆盖项目根同名 exe。

## 6. 构建

### 6.1 一键构建

```bat
build_launcher.bat
:: 或
"..\runtime\python.exe" scripts\build_launcher.py
```

构建步骤（脚本内带每步耗时与总耗时）：

1. 检查构建环境（Windows / `main.py` / Pillow / csc.exe / 输出目录）；
2. Pillow 绘制原创坦克剪影图标 → `assets/app.ico`（六种尺寸并回读校验）；
3. 生成临时 C# 源码（纯 ASCII，中文用 `\uXXXX` 转义，避开 csc 源码编码坑；
   同时按 `src/config.py` 的版本号写入 `AssemblyVersion` / `AssemblyFileVersion` 等资源版本信息）；
4. `csc.exe /target:winexe` 编译 → 先出 ASCII 临时名再部署为中文文件名（避免编译器 Unicode 路径风险）；
5. 部署到项目根并自检 `exe --version`（校验退出码 0 与 `v0.2.0`，版本自动读取 `src/config.py`）。

### 6.2 参数

| 参数 | 说明 |
| --- | --- |
| `--check` | 只检查构建环境，**不写任何文件** |
| `--csc PATH` | 指定 `csc.exe`（默认自动搜索 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`，再回退 Framework/PATH） |
| `--out PATH` | exe 输出路径（默认项目根 `坦克世界封号查询.exe`） |
| `--icon PATH` | 图标输出路径（默认 `assets/app.ico`） |
| `--skip-verify` | 跳过 `exe --version` 自检 |
| `--keep-work` | 保留临时工作目录（排查编译问题用；默认落在 `%TEMP%\wot_ban_launcher_*` 并自动清理） |

### 6.3 依赖

- 共享解释器 `..\runtime\python.exe`（Python 3.12 + Pillow 12.x，仅构建期需要）；
- Windows 自带 .NET Framework 4.x 的 `csc.exe`（无需安装 Visual Studio / .NET SDK）；
- 运行期只需目标机器有 `runtime\pythonw.exe`（便携包）或 PATH 中的 Python 3.10+。

### 6.4 便携包集成（scripts/build_portable.py）

`scripts/build_portable.py` 的组装步骤已同步加入启动器相关文件：

- 复制项目根 `坦克世界封号查询.exe`、`assets/app.ico`、`docs/P4-启动器.md` 进便携包
  （缺 exe 时构建直接报错，提示先跑 `build_launcher.bat`）；
- 内嵌 CPython 放在包内 **`runtime\`** 目录（与启动器第一顺位解析 `<app根>\runtime\pythonw.exe` 一致），
  便携包解压后**双击 exe 即可运行**，无需安装 Python；
- 便携包自检新增一项：用包内 `坦克世界封号查询.exe --version` 验证「启动器 + 内嵌运行时 + 源码」布局可用；
- 生成的是便携版 `run.bat` 仍直接调用包内 `runtime\pythonw.exe`：bat 受"全 ASCII + CRLF"硬规范约束，
  无法可靠引用中文 exe 文件名，因此定位为**ASCII 备用入口**，用户主入口是双击 exe。

## 7. 图标原创声明

`assets/app.ico` 由 `scripts/build_launcher.py` 中的 `draw_icon_background` / `draw_tank_silhouette`
**用 Pillow 图元（圆角矩形 + 多边形 + 椭圆）从零绘制**：

- 深橄榄绿圆角渐变底 + 米色坦克剪影（履带、负重轮、梯形车体、炮塔、炮管与炮口制退器），
  这些是通用几何图形，**不复制、不描摹任何游戏官方图标/素材**，也不使用 `game.ico`；
- 仅 256 坐标系的几何参数与配色，全部在脚本内可改可复现；多尺寸逐级单独绘制并超采样缩小，
  16/32 px 下会自动省略负重轮与指挥塔细节，保证轮廓清晰；
- 该图标仅用于本仓库"非官方查询工具"的桌面入口，**不与任何游戏厂商商标混淆**；
  如后续需要换标，只需修改脚本中的绘制函数或替换 `assets/app.ico`（保持六种尺寸）后重编。

## 9. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 弹「未找到 main.py」 | exe 被单独移动了；请把 exe、`main.py`、`src\`、`runtime\` 放在同一应用根目录 |
| 弹「未找到可用的 Python 运行环境」 | 应用根下无 `runtime\`，上级也无开发布局 `..\runtime\`，PATH 也无 Python；按提示补 runtime 目录或安装 Python 3.10+ |
| `--version` 无输出 | 在 PowerShell 中用 `&` 调用 GUI 子系统 exe 不会等待；改用 `cmd` 或 `Start-Process -Wait` |
| 覆盖 exe 失败 | 旧启动器/杀软正在占用，先关闭再重编；或 `--out` 输出到别处 |
| 图标在资源管理器里没变 | Windows 图标缓存；把 exe 改名或重启资源管理器后刷新（不影响实际图标） |
| 重编后 exe 体积变大 | 检查 csc 是否被换成 .NET SDK 版本；`--check` 会显示实际使用的 csc 路径 |
